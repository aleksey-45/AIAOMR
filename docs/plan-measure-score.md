# 小节打分与分流（设计稿）

> 状态：**设计稿，还没实现，也没进 `spec-v3.md`。** 这份文档回答一个问题：把"这一小节通过 /
> 不通过"的二值判断换成连续分数，再按分数分三档处理——直接通过、AI 复审、判为错误。
> 实现前先按 §7 做离线校准，再写代码。

## 1. 为什么改

现在的判断是二值的：小节时值之和等于拍号就过，不等就报警，整首写不出 `.gp5` 就阻断。
P1 的 0/4 就是被这个机制卡住的——四首歌各有一批小节对不上，但没人知道哪几小节是真的读错、
哪几小节只是排版或休止符的边角情况。二值判断有两个问题：

- **不同性质的证据被压成一个布尔。** "没标拍号"、"时值和差 8 tick"、"数字比音头多一个"、
  "几何和模型在第三拍上不一致"，严重程度完全不同，却都叫"不通过"。
- **复审很贵，只能花在值得的小节上。** 一次盲读复读约 ¥0.0025–0.0035，79 小节全复审就是
  把钱撒在本来没问题的小节上；反过来只复审"报警"的小节，又会漏掉"没人报警但其实错了"的。

分数要解决的就是这两件事：让严重程度可比较，让复审有优先级。

## 2. 分数从哪来

每一小节一组证据项，每项给一个 0..1 的把握分（或一个惩罚分），加权合成 0..100 的小节分。
分数是**证据的汇总**，不是概率，不能当"这一小节对的概率"用。

### 2.1 结构证据（音乐上说得通吗）

| 证据 | 来源 | 好 | 坏 |
|---|---|---|---|
| 时值之和 vs 拍号 | A1 | 完全相等 = 1 | 差得多 = 0；差 1 个 tick 给部分分 |
| 音头 / 数字对账 | A4、A4b | 数量一致且绑定完整 = 1 | `D > H` 或未绑定的音头 = 0 |
| 调弦反解 | A5 | 众数与声明调弦一致 = 1 | 不一致 = 0（但降权，因为调弦读错影响全曲） |
| 连音两端音高 | A6 | 全部一致 = 1 | 每条不一致扣分 |
| 印刷小节号链 | A7 | 严格递增 = 1 | 断裂 = 0 |
| 字形模板 vs 模型品数 | A8（未实现） | 全一致 = 1 | 逐条扣分 |

### 2.2 读数证据（这次调用可信吗）

- schema 重试次数：重试 1 次 0.7，2 次 0.4，仍失败 0；
- 空返回、`unreadable`：直接 0（硬否决）；
- 复读与首读逐拍不一致：按不一致拍的占比扣分；
- 一拍都没读到（`beats` 为空）而小节有符号：直接 0（硬否决）。

### 2.3 几何证据（五线谱这条线说了什么）

- `MeasureRhythm.status`：`ok` = 1，`partial` 按判出的拍占比，`unknown` = 0（硬否决）；
- 几何与模型逐拍时值一致率：一致拍数 / 可比较拍数；
- 几何 abstain 原因：`AR-05`（和不对）比 `AR-02`（字形不认识）更可疑；
- 符号置信度（`RhythmBeat.confidence`）按拍的均值。

### 2.4 图像证据（这一小块清楚吗）

- 有效 deg 与配置下限的比值（`read.min_deg_eff` 之下扣分）；
- 裁片像素是否达到 1.6 MP（P0 实测：低于这个数准确率明显下降）；
- 二值化后谱线厚度是否异常（> 0.5×deg 说明糊了）。

### 2.5 合成

```
score = 100 × Σ(w_i × e_i) / Σ(w_i)          # 所有证据项加权平均
score = min(score, hard_cap)                  # 有硬否决项时直接压到错误档
```

权重初值（待校准，写进 `configs/thresholds.toml` 的 `[route.weights]`）：结构 0.45、
读数 0.25、几何 0.20、图像 0.10。硬否决项：`unreadable`、无生效拍号、几何 `unknown`
且模型自相矛盾、`D > H`。

## 3. 三档处理

| 分数区间 | 档位 | 动作 | 成本 |
|---|---|---|---|
| `≥ T_pass`（建议 85） | 直接通过 | 不再复审，直接进装配 | 0 |
| `T_review ≤ s < T_pass`（建议 55–85） | AI 复审 | 盲读复读（只给报警规则与 claim/expected），必要时终裁；结果回写并重算分数 | 每次调用 ≈ ¥0.003 |
| `< T_review`（建议 55） | 判为错误 | 不自动补写；该小节标 `unknown`，进报告；按整曲策略决定是否阻断 | 0 |

规则：

- **阈值只进配置**，不许散落在代码里；调整阈值要单独提交并写明依据（照 §6 的校准结果）。
- **复审有上限**：每首最多 `adjudicate.max_rounds` 轮；同一小节复审后分数没提高就停，
  不许无限循环。
- **复审按分数从低到高排队**：预算花完时，剩下的小节按"判为错误"处理，而不是跳过不管。
- **终裁仍然盲读**：分数只决定"要不要送终裁"，不决定终裁结论。这条不能反过来。

## 4. 与现有规则的关系

- **"报警不阻断"不变。** 报警从"结论"降级为"证据"：分流决定动作，报警决定分数。
- **abstain 不变。** 几何说不清就 abstain；abstain 会压低分数，但程序仍然不猜。
- **三条铁律不变**：判不准就 abstain、不用和校验反推时值、不按拍格切图。
- 真正会阻断的仍然只有三种：图片没法用、成本超预算、写出的文件通不过自检。分数低到
  "判为错误"档时，**标 unknown 继续跑完**，不阻断；最后在报告里统一列出低分小节，
  由人决定改哪几处。这是已定的口径（2026-10-19），与 P1 的"当场阻断"不同，是有意的改变：
  一个小节的错误不该让整首歌交不出文件。

`metrics.json` 里加：分数直方图（十档）、三档计数、复审花费、复审改判率、按档的最终正确率。

## 6. 校准（必须离线做，不烧钱）

1. 用四首真值（`corpus/truth/*.gp5`）+ P1 录制好的模型响应，离线回放整条流水线；
2. 对每个小节算出分数，并与真值逐拍比对，得到"分数 vs 真的对不对"的散点；
3. 画 ROC / PR，选 `T_review`、`T_pass`：`T_review` 选在"复审改判率开始下降"的位置，
   `T_pass` 选在"再降低几乎不抓错"的位置；
4. 给出混淆表：**放过的真错**（低分被直接通过）与**误复审**（高分被送复审）各自的条数；
5. 校准结果写进 `docs/`，阈值写进配置，报告里写明"这一版阈值是在哪份数据上定的"。

校准数据不够时（比如只有四首），阈值只能当初始值，报告里必须写清样本量。

## 7. 风险与未决

- **分数不是概率。** 不许在报告里说"这一小节有 85% 的把握是对的"；只能说分数。
- **分数与"客观错误"不等价。** 一个小节可以"小节和都对、音全错"——那靠 A2/A8/审计抓，
  不靠这个分数。分数管的是"节奏与结构"这条线。
- **阈值会漂移。** 不同刻谱、不同清晰度（class 1/3/5/6）需要分档阈值；先把 class 3 定住。
- **错误档的出口已定**：标 unknown 继续跑完，报告里统一列出低分小节（见 §4）。
  剩下的风险是"错误太多时报告会长"，需要在报告里按分数升序排、并给出前若干个的裁片路径。
- **复审可能被 claim 带偏。** 盲读要只给规则和 claim/expected；至少抽一半做"不给 claim"
  的对照，量一下带偏率。
- **分数解释性。** 每项证据都要在事件里给出 `rule/weight/score`，否则人看到 42 分不知道为什么。
