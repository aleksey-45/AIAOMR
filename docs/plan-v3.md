## 1. 一句话方案

> **几何定坐标，VLM 定符号，TAB 定音，记谱定时，程序验算，模型终裁。**

旧项目的结论其实是对的——"印出的数字是品位，记谱只提供节奏"（`reader/report.py:98-105`）。它错的地方只有一处：**让几何去数拍子**。v3 只换这一件，其余照搬。

## 2. 背景

### 2.1 AIAOMR 的实测结论（放弃了什么）

代码 6689 行 Python + 2474 行 Markdown；2026-09-27 至 10-17；产出 2 个 `.gp5`。

| 指标（`tools/accuracy.py`，同一把尺子） | 老人与海（全八分） | NIGHT DANCER | 打上花火 |
|---|---|---|---|
| 对齐佐证 `rest_pattern`（阈值 0.99） | 1.000 | 1.000 | 1.000 |
| 弦位+品位 `string_fret`（阈值 0.90） | ✓ | 0.974 | 0.902 |
| 音高+时值 `pitch_exact`（阈值 0.80） | ✓ 111 beats 全 read | 0.667 | **0.525** |
| 小节时值自洽 `bars_add_up`（阈值 0.95） | ✓ | 0.564 | 0.574 |

输入档实测：

| 输入档 | 结果 |
|---|---|
| 干净导出 PNG | 可用（弦位+品位 0.974） |
| B 站滚动视频截图 | 可用但 27 项硬失败、从未交付 |
| 手机照片 | **0 小节**（谱线弯 30px、线厚 3–4px） |
| 4 线 TAB + 简谱 | **结构性 0 小节**（`no notation staff`） |

**死因（按权重）**：

1. **节奏是墙，墙后是数据问题**。空心符头试了 3 次全败，附点/连音/休止字形逐项手写判据，作者自己在 `docs/notes-read-system.md:54` 写下"正确做法需要带标注的语料来调参"。
2. **每份刻印都要重新调参**。`area>150`、`margin 250`、`lineFrac 0.72` 逐个换成 deg 倍数，等于为每个出版社交一次税。
3. **没有操作者**。整个仓库的契约是"工具报事实 → AI 决策 → 人确认"（`AGENTS.md` 3200 token 预算、子代理盲测、CLI 暴露面锁），需要**一个 AI agent 当司机**，交不到用户手上。

### 2.2 AllegScore 的实测结论

homr 的 GUI 前端；功能 10 个任务 + 打包 4 个任务全部标记完成，但：

- 只修 MusicXML 头（乐器/BPM/谱号/调号/拍号），**音符级修正明确是非目标**；
- homr 输出 `<technical>` 0 个——**TAB 完全没读**；
- 打包版 `launcher.py:117` 用 `sys.executable -m uvicorn`，PyInstaller 下自指，**从未启动过服务**；`.7z` 是坏档；无任何自动化测试。

死因：**把最贵的正确性留给人，却不给人修正的手段**；且方向反了——想从音高反推 TAB（不可判的逆问题）。

### 2.3 v3 的回答

两个旧项目都绕开了同一个问题："人怎么纠正错误"。v3 的回答是：**不给人纠正**——把判断权交给模型，用离线语料兜底。

## 5. 架构与角色

### 5.1 五层

> 代码按依赖方向分四层：`providers`(L1) → `measure`(L2) → `score`(L3) → `writers`(L4)，共享 `kernel`。下表是"逻辑角色"，与四层是正交视角：定位/验算/终裁/装配都落在 L3。

| 层 | 实现 | 做什么 | 明确不做 |
|---|---|---|---|
| **定位** | 纯 CV（OpenCV/numpy） | 页→系统→小节网格、TAB 弦线 y、deg、音头/数字 blob 坐标、裁片、跨帧对齐 | 不下任何语义结论 |
| **读取** | DeepSeek 视觉 | 每小节 events、骨架（分级，见 spec §2.2） | 不写 IR、不写文件 |
| **验算** | 纯程序 | 四条不变量 + 计数/范围/调弦/往返/审计 | **不阻断交付**，只产生报警 |
| **终裁** | DeepSeek 视觉 | 报警回灌后的判定，可推翻前面任何结论 | — |
| **评测** | 纯程序 | 带分母打分、`--selftest` | 永不出现在交付路径 |

### 5.2 责任边界（一句话）

> 程序只提供"坐标 + 事实 + 疑问"，从不下结论；**结论全归模型**。

### 5.3 一条重要简化 + 三条修正

音高由 TAB 反解，因此**谱号对最终 `.gp5` 不产生影响**（GP5 的音高 = 调弦 + 品位）。

但有三条必须修正：

1. **调号不是"无所谓"**。它不影响最终音高，但会影响两件事：① VLM 读五线谱时的升降号判断（`pitchClaim`），错一个调号 → A2 假警报连片、把系统性偏移"修"进谱里（旧项目原话）；② GP5 里的调号显示。所以调号是 **P1 重要**，不是可选项。
2. **总小节数不读**。它没有验证机制（旧项目纯声明）、极易读错、且没有任何用途——A7 用印刷小节号链就够了。`measureCount` 改为 `len(measures)` 推导。
3. **中途换拍号/换调号必须支持**。`Don't Cry` 就有 `2/4 → 4/4` 的换拍，旧项目只有全局 `timeSignature` 直接读错。现在拍号/调号都是**事件列表**，并且用 A11/A12 聚类检测兜底（就算没看见记号，小节时值也会立刻对不上）。

所以真正致命的是：**拍号（含变化）× 调弦 × 弦数 × 结构**；调号次之；速度/曲名/作者可以用默认值兜底。

## 7. 数据流

```
S0 定位（几何）
   输入：原始图片/截图
   输出：systems[]（五线谱带 y 范围、TAB 带 y 范围、deg、弦线 y[]）、
         measures[]（x 范围、印刷小节号）、crops[]、几何提示
   判定：小节宽度离群检查；印刷小节号链自洽（**不比对总小节数**——那个数不读）
   失败：报"这张图不能用" + 原因，不产出

S1 读取（VLM）
   输入：系统裁片（0.9–1.6MP）+ 几何提示 + 骨架（拍号/调弦 P0，调号 P1，速度/曲名 P2–P3）
   输出：每小节 events JSON（时值/休止/连音/string/fret/技巧）
   判定：JSON schema 校验；空返回重试
   失败：重试 2 次 → 拆成 4 小节更小裁片再读

S2 验算（程序）
   输入：S1 结果 + 定位数据
   输出：报警清单（§9）
   判定：四条不变量 + 计数/范围/调弦
   失败：报警项进入 S2b

S2b 复读（VLM）
   输入：报警小节的另一种裁片（4 小节放大 / 只给该小节）+ 报警原因
   输出：修订后的 events
   判定：V2 投票（两次一致则过）

S3 终裁（VLM）
   输入：两次仍不一致的小节
   输出：最终判定 + 理由 + 引用坐标
   约束：可推翻 S1/S2b 的任何结论

S4 装配（程序）
   输入：全部小节判定
   输出：canonical IR（§8）
   判定：小节编号链；多小节休止展开数量；反复展开可枚举

S5 导出（程序）
   输入：IR
   输出：.gp5（+ 内部保存 IR、决策日志）
   判定：validate → build → verify（ROUND-TRIP）→ alphaTab audit

S6 评测（程序，内部）
   输入：truth 语料 + IR
   输出：分档指标 JSON
   判定：阈值先声明；低于阈值 exit 1
```

## 8. canonical IR

唯一事实来源。`.gp5` 只是构建产物。

```jsonc
{
  "version": "3.0",
  "source": { "kind": "image|screenshots|video_strip", "class": 1|3|5|6, "files": ["..."] },
  "score": {
    "title": "", "artist": "", "tabber": "",
    "tempo": 96,
    "tuning": [28, 33, 38, 43],        // MIDI，低→高
    "stringCount": 4,
    "timeSignatures": [{ "measure": 1, "beats": 4, "beatType": 4 }],
    "keySignature": "BMajor",
    "clefTranspose": -12,               // 跟 GP 惯例：贝斯高八度记谱
    "fretCount": 24,
    "measureCount": 107
  },
  "measures": [
    {
      "index": 1,
      "printed": 1,                     // 谱面印刷号（可空）
      "rest": true,                     // 整小节休止
      "multiRest": 2,                   // 多小节休止条数（展开后仍保留记录）
      "beats": [
        {
          "duration": "eighth",         // whole|half|quarter|eighth|16th|32nd
          "dots": 0,                    // 0|1|2
          "rest": false,
          "notes": [{ "string": 1, "fret": 6, "tie": false }],
          "techniques": [],             // slide|hammer|pull|vibrato|mute|harmonic|...
          "prov": "read",               // read | derived
          "evidence": { "system": 1, "crop": [l, t, r, b], "call": "s1-003" }
        }
      ]
    }
  ],
  "structure": {
    "repeats": [{ "start": 1, "end": 8, "times": 2 }],
    "endings": [{ "measure": 8, "number": 1 }],
    "jumps":   [{ "type": "dc|ds|dcAlCoda|dsAlCoda|toCoda", "measure": 12 }],
    "sections":[{ "measure": 17, "label": "Chorus" }]
  },
  "judgements": [
    { "id": "j001", "measure": 12, "rule": "bar_duration",
      "claimed": 4320, "expected": 3840, "final": 3840,
      "reason": "…", "model": "deepseek-flash", "crops": ["…"] }
  ],
  "build": { "gp5": "…", "roundtrip": "OK", "audit": { "pitch_mismatch": 0, "bar_errors": 0 } }
}
```

约定：

- `string 1` = **最低音弦**（贝斯 E=1，G=4）；导出时在 `gp_build` 里统一翻成 GP 的"1=最高弦"。
- IR 用 `duration` 基础名 + `dots` 整数；导出映射到 `gp_build` 的命名：`"eighth"` / `"dottedEighth"`。**`gp_build` 当前只支持单附点**（`DOTTED` 字典），双附点（`dots: 2`）需要扩展，列为 P2 的工作项（贝斯谱里罕见）。

## 9. 报警器（只报警，不阻断）

| ID | 规则 | 触发后动作 |
|---|---|---|
| A1 `bar_duration` | 有音符小节的时值之和 ≠ 拍号 | 复读该小节（4 小节放大） |
| A2 `pitch_identity` | `MIDI(pitch) ≠ tuning[string-1] + fret` | 复读 + 几何字形比对 |
| A3 `range` | `fret < 0` 或 `fret > fretCount` 或 `string ∉ 1..N` | 复读 |
| A4 `number_head` | 数字 **>** 音头（`数字 ≤ 音头` 是正常 TAB 记法；**比"数字"不比"字形"**） | 复读 |
| A4b `unexplained_head` | 一个音头没有对应数字、且未标 `tieFromPrevious` | 复读 |
| A5 `tuning_implied` | `音高−品位` 的众数 ≠ 声明的调弦 | 复读 + 骨架复核 |
| A6 `tie_pitch` | 连音两端音高不同 | 复读 |
| A7 `bar_number_chain` | 印刷小节号不递增 / 与累加冲突 | 骨架复核 |
| A8 `digit_disagreement` | 几何字形标签 ≠ 模型读出的 fret | 复读 + contact sheet 投票 |
| A9 `multirest` | 多小节休止条数缺失或 ≤ 0 | contact sheet 一次读完 |
| A10 `self_reported` | 模型自报"看不清" | 复读 |

**原则**：报警器是模型注意力的入口，不是闸门。`REFUSING TO BUILD` 在 v3 中不存在——所有报警都必须有终裁记录，但不阻止导出。

## 10. 定位层规格

### 10.1 必须做的测量

| 量 | 方法 | 精度目标 |
|---|---|---|
| 系统范围 | 5 线谱线组与下方 TAB 线组配对（间隔 60–400px，TAB 线距 > 1.2× 谱线距） | 系统召回 ≥ 0.98 |
| TAB 弦线 | 行投影 + 线距聚类 | ±0.5 px |
| 小节网格 | 列投影找小节线；谱号区宽度 < 0.45×中位宽则并回 | 小节数误差 0 |
| 印刷小节号 | 跑第一条小节线上的数字 | 命中 ≥ 0.9 |
| deg | 谱线间距（像素） | ±1 px |

### 10.2 裁片规格（与 DeepSeek 对齐）

| 项 | 值 |
|---|---|
| 单位 | 1 个完整系统（五线谱带 + TAB 带） |
| 像素 | **0.9–1.6 MP**，长边 ≤ 2500 |
| 硬约束 | **必须包含谱号/调号** |
| 复读裁片 | 4 小节（0.8–1.6 MP）或单小节 |
| 微问题 | contact sheet 拼 9–12 个，**绝不单发** |

### 10.3 旧项目踩过、必须写进实现的坑

1. `find_systems` 的行覆盖率阈值必须 ≤0.60：TAB 底线被印在线上的数字打断后整行占比只有 0.703。
2. **短末行**（只占页宽约 34%）在任何全页宽度阈值下都不可见，需按局部宽度定位。
3. 谱号区与 `||:` 反复线是两条竖线，按宽度（<0.45×中位宽）识别后并回，否则小节号整体 +1。
4. `margin` **不可叠加**：谱号区已单独排除时只留 20 px pad，否则会吃掉首小节的第一个数字。
5. 所有读图入口必须做 `exif_transpose`（手机照片）。
6. **>64 MP 必须先切片**（实测 `老人与海#1.png` = 71.8 MP 会直接报错）。
7. 真谱线是"细（2–4 px）且长"；letterbox 黑边/进度条会**很粗（>25 px）或整幅宽**。
8. class 5/6 的 UI 元素：跨帧中值可消（瞬态），但**弹幕压住音符**只能裁掉或报不可用。

## 11. 读取层规格（DeepSeek）

| 项 | 值 |
|---|---|
| 模型 | `deepseek-flash`（**唯一支持视觉的模型**，v4-pro 无视觉） |
| 调用方式 | OpenAI 兼容 `/chat/completions`，base64 data URL；图只能放 **user** 消息 |
| `detail` | `original`（`low` 会压到 512×512，不可用） |
| 每图 token | `1024 × clamp(P, 0.296MP, 1.69MP) / 1.69MP`，下限 180、上限 1024 |
| 尺寸上限 | 单边 ≤8192 px（**≥15 张图时降到 4096**）；单图 ≤32 MiB；每请求 ≤600 张；请求体 ≤48 MiB |
| 输出 | `response_format={"type":"json_object"}` + prompt 里出现 "json" + 给示例 |
| 已知缺陷 | **偶发返回空内容** → 结构化校验 + 重试 2 次 + 拆小裁片 |
| 并发 | 18 路（API 并发上限 2500） |
| 成本 | **每 8 小节 ≤ ¥0.0150**（人民币·**谷价**口径，四位小数；thinking 关≈¥0.0047、开≈¥0.0127）；单首 107 小节 ≈ **¥0.07–0.18** |
| 墙钟 | **12–20 s/首** |

### prompt 必须带的东西

0. **骨架由一次"页眉/首页裁片"调用单独读**，按优先级：**P0 拍号（含变化）+ 调弦/弦数**、**P1 调号（含变化）**、**P2 速度**、**P3 曲名/作者**；**不读总小节数**。这一调用在 S1 之前，产出 `score{}` 与 `skeletonProvenance`。
1. 该系统的小节 x 范围、印刷小节号；
2. **TAB 弦线 y 坐标**（让模型输出 `string` 而不是自由发挥）；
3. 调弦、弦数、拍号、调号；
4. 严格的 JSON schema + 一个最小示例；
5. 禁止事项：不要输出 IR、不要补全看不清的内容、看不清就写 `unreadable`。

## 12. 终裁与投票

| 票型 | 做法 | 用在哪 |
|---|---|---|
| **V2 跨表征** | 同一小节读两次（整系统裁片 vs 4 小节放大裁片） | 报警项 |
| **V3 自洽** | 模型自己给的 `(string, fret)` 与 `pitch` 必须符合恒等式 | 全部小节（零成本） |

不做"同 prompt 重复采样"——温度低时几乎必然一致，白花钱。

终裁输入：两次结果 + 报警原因 + 两张裁片。输出：最终值 + 理由 + 引用坐标，写入 `judgements[]`。

## 14. 导出与审计

```
gp_build.py：validate → build → verify
   validate：调弦升序、string ∈ 1..N、小节 ticks、品位范围、未知时值
   build   ：显式 append + BeatStatus.normal；清掉默认吉他轨；string 翻转只此一处
   verify  ：重新 parse 逐音符比对 → ROUND-TRIP OK
   cp936   ：title/artist/album/tabber 逐字段 encode，编不进则拒绝写出
gp_audit.mjs（alphaTab，独立第二意见）：
   不变量 A：音高 == 空弦 + 品位
   不变量 B：小节时值 == 拍号
```

交付物：`.gp5`（唯一）。内部保留：IR、决策日志、每次调用的原始返回。

## 20. 附录

### A. 本机实测参考（决策依据）

**DeepSeek 视觉**（官方文档核实 + 本机读图实测）

- 单图 token 上限 1024、下限 180；<544×544 会被放大；>1.69MP 会被缩到约 1300²。
- 本机读图实测：2 小节 0.35MP 与 deg=8 两档，TAB 数字/附点/连音/滑音均读对；1.6MP 放大版读出相同内容、贵 4.6 倍。
- DSH `read_image`：硬上限 64,000,000 像素（超了直接报错）；有效压缩到约 1.6MP / 长边约 2520。

**homr（已否决，仅留记录）**

- 39 M 参数 / 157.6 MB fp32（segnet 14.3M + encoder 13.2M + decoder 11.8M）。
- CPU：单进程默认 8.95 s/系统；`intra_op_num_threads=2` → 4.89 s；8 路并行 → 1.71 s/系统；716 MB/进程。
- 否决理由：**太慢**（用户决定），且 AGPL-3.0。实测它读五线谱的能力较强（打上花火一页 21/24 小节时值正确、23 个附点），将来若要离线第二意见可随时接回。

### C. 为什么不上 homr / 不上 GPU（决策记录）

- **homr**：实测 1.7 s/系统（8 路并行）→ 一首 30 s；视觉 API 并发 18 路 → 一首 12–20 s。速度更差 + AGPL 污染 + 引入 39M 参数依赖，收益不抵成本。
- **GPU**：本机 onnxruntime 为 CPU-only，3060 空转；即便装 GPU 版，homr 的瓶颈是模型加载与逐 token 自回归，收益有限。且用户明确"先不上 GPU"。
- **视觉 API 的并发上限 2500** 意味着墙钟瓶颈不在 API，在本地几何——所以并行策略是"18 路请求 + 几何串行 10 s"，而不是本地模型堆机器。
